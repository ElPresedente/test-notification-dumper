# Notification Dumper

Маленький Android-дампер для проверки уведомлений Mir Pay и банков перед разработкой «Копилки».
Kotlin, нативный Android UI, Android 9+, без сервера и разрешения INTERNET.

## Скачать APK без Android Studio

1. Открой [Actions → Android APK](https://github.com/ElPresedente/test-notification-dumper/actions/workflows/android.yml).
2. Выбери последнюю успешную сборку (зелёная галочка).
3. Внизу в **Artifacts** скачай **notification-dumper-apk**. Для скачивания нужно войти в GitHub.
4. Распакуй ZIP и установи `notification-dumper.apk` на телефоне. При необходимости разреши установку APK выбранному браузеру/файловому менеджеру.

Сборка запускается при push в `main`, для PR и вручную через **Run workflow**.
В архиве также есть SHA256SUMS.txt. Это тестовый debug APK, не релиз для магазина.
Стандартный debug-ключ на чистом CI runner может меняться: если обновление поверх старой версии не устанавливается,
сначала экспортируй нужные записи, затем удали старое приложение и установи новое.
Для постоянного приложения позже понадобится отдельный стабильный ключ в GitHub Secrets.

## Проверка перед покупкой

1. Запусти приложение → **Доступ к уведомлениям** → разреши доступ Notification Dumper.
2. Вернись и дождись **Слушатель подключён**. При необходимости нажми **Переподключить слушатель**.
3. Нажми **Начать запись**, затем **Тестовое уведомление**. На Android 13+ разреши приложению показывать тестовые уведомления.
4. Счётчик должен увеличиться. Удали тестовое уведомление из шторки — получишь ещё и событие удаления.
5. Нажми **Остановить и сохранить** → **Отправить** или **Сохранить как…**.

Если Android запрещает включить доступ для APK, установленного из файла:
Настройки → Приложения → Notification Dumper → меню ⋮ → **Разрешить ограниченные настройки**, если этот пункт доступен.
Название и расположение зависят от Android/One UI. На управляемом устройстве доступ может быть запрещён администратором.

Перед реальной оплатой начни новую запись за 10 секунд. Приложение можно свернуть.
Оплати Mir Pay, подожди 10–20 секунд, вернись, останови запись и отправь JSONL.
Запись не прекращается при повороте экрана или обычном сворачивании. Не нажимай системное «Остановить» для приложения во время опыта.

## Что сохраняется

Одна строка = один JSON-объект; UTF-8, JSONL.

- `session_start` / `session_stop`, версия схемы, модель телефона, Android и часовой пояс.
- `snapshot` — уже активные уведомления при старте или переподключении; это **не новая покупка**.
- `posted` — создание **или обновление** уведомления. Повторяющийся `key` позволяет связать обновления.
- `removed` — удаление с числовым `removalReason` Android.
- `listener_connected`, `listener_disconnected`, диагностические ошибки.
- Последовательность `seq`, время получения UTC + epoch milliseconds + монотонное время.
- Пакет, id/tag/key, uid/userId, postTime, группировка и признаки состояния.
- Публичные поля Notification, channel/ranking, actions, remote inputs, intents (только метаданные).
- Все ключи `extras`: класс значения и рекурсивное значение; Bundle, массивы и списки поддерживаются.

Неизвестные Parcelable, Icon и RemoteViews представлены классом и `toString`, а не полным внутренним содержимым.
Пиксели Bitmap не сохраняются. Ограничения сериализации (глубина 12, массивы/списки 1000 элементов,
текст 262144 символа) явно помечаются в JSON. PendingIntent никогда не выполняются.
Android может скрыть чувствительные данные, недоступные слушателю уведомления или часть полей при удалении.
Уведомления, которых приложение не публикует в Android, поймать этим способом нельзя.

## Хранение и ограничения

Данные пишутся в приватные файлы приложения через последовательную очередь, не в сеть и не в logcat.
Остановка ждёт очередь и синхронизирует файл перед экспортом. Файлы доступны через read-only URI с временной выдачей доступа.
Облачный Android backup выключен. Дамп включает уведомления **всех** доступных приложений — перед отправкой проверь личные сообщения.
Разрешение POST_NOTIFICATIONS требуется только для кнопки теста; доступ к чтению уведомлений включается отдельно.

После убийства процесса/перезагрузки запись **не возобновляется автоматически**: частичный файл остаётся,
приложение показывает прерывание. Отсутствие `session_stop` означает неполную сессию;
при аварийном завершении последний JSONL-объект может быть неполным. Отключение слушателя отмечается в файле,
если процесс ещё жив; пропущенные события восстановить нельзя.
Покупку на реальном Samsung/Mir Pay необходимо проверить отдельно — успешная сборка этого не доказывает.

## Локальная сборка (необязательно)

JDK 17 и Android SDK 35, затем:

```sh
./gradlew assembleDebug lintDebug
```

APK: `app/build/outputs/apk/debug/app-debug.apk`.
